# Security Policy

## Supported Versions

This project is actively maintained on the latest `main` branch and the most recent published build. Security updates are prioritized for the currently supported version in active use.

| Version / Branch | Supported |
| --- | --- |
| `main` / latest release | :white_check_mark: |
| Older released builds | :warning: Best effort only |
| Unmaintained or archived forks | :x: |

If you are running an older copy of the project, we strongly recommend upgrading to the latest version before exposing it publicly.

## Reporting a Vulnerability

Please do not open a public GitHub issue for security vulnerabilities.

Instead, report the issue privately through GitHub Security Advisories for this repository, or contact the maintainer directly through a private channel if a Security Advisory is not available.

Please include:

- A description of the issue and its impact
- Affected version or commit hash
- Steps to reproduce the vulnerability
- Any suggested mitigation or fix

We aim to acknowledge valid reports within 5 business days and will work with you on a coordinated disclosure timeline.

## Disclosure Expectations

We appreciate responsible disclosure and will do our best to:

- validate the report
- assess the severity and affected scope
- provide a remediation timeline when possible
- credit reporters if they prefer to be acknowledged

If a report is accepted, we will work to release a fix as quickly as possible. If a report is declined, we will explain the reasoning and, where appropriate, suggest additional hardening steps.
